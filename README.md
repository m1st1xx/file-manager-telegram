# 📁 File Manager Telegram Bot

> Telegram-бот для управления личным файловым хранилищем прямо из Telegram.

**File Manager Telegram Bot** — это Telegram-интерфейс для файлового хранилища, позволяющий пользователям загружать, скачивать и удалять свои файлы, организованные по предметам/категориям.

Бот работает совместно с веб-версией файлового хранилища и использует **общую базу данных и директорию с файлами**, благодаря чему изменения, выполненные через Telegram, сразу доступны на сайте и наоборот.

---

## ✨ Возможности

### 👤 Авторизация

* Регистрация пользователя через Telegram
* Привязка Telegram ID к аккаунту
* Совместимость с пользователями веб-версии
* Восстановление авторизации после перезапуска бота
* Защита файлов от доступа других пользователей

### 📤 Загрузка файлов

Пользователь может:

1. Выбрать раздел/предмет
2. Отправить файл в Telegram
3. Получить подтверждение загрузки

Файл автоматически сохраняется в файловое хранилище пользователя.

### 📥 Скачивание

Бот отображает доступные файлы пользователя и позволяет скачать их непосредственно в Telegram.

Поддерживается работа с Unicode-именами файлов, включая:

* 🇷🇺 русский язык
* 🇬🇧 английский язык
* другие Unicode-символы

### 🗑 Управление файлами

Пользователь может удалять ненужные файлы непосредственно из Telegram.

Удаление производится из общего файлового хранилища, поэтому удалённый через бота файл также исчезает из веб-интерфейса.

## 🏗 Архитектура

Проект рассчитан на совместную работу с веб-приложением File Manager.

```text
                    ┌─────────────────────┐
                    │       Telegram      │
                    │       Client        │
                    └──────────┬──────────┘
                               │
                               ▼
                    ┌─────────────────────┐
                    │   Telegram Bot     │
                    │      aiogram       │
                    └──────────┬──────────┘
                               │
                    ┌──────────┴──────────┐
                    │                     │
                    ▼                     ▼
             ┌─────────────┐       ┌─────────────┐
             │   SQLite    │       │   uploads/  │
             │    DB       │       │    files    │
             └─────────────┘       └─────────────┘
                    ▲                     ▲
                    │                     │
                    └──────────┬──────────┘
                               │
                               ▼
                    ┌─────────────────────┐
                    │    File Manager     │
                    │       Website       │
                    └─────────────────────┘
```

Главный принцип проекта — **единое файловое пространство**.

Бот не создаёт отдельную копию файлов и не использует отдельное файловое хранилище.

Он работает непосредственно с существующими:

```text
users.db
new_users.db
uploads/
```

---

## 🌐 Размещение на серверах

Проект также рассчитан на ситуацию, когда Telegram API и файловое хранилище находятся на разных серверах.

Например:

```text
🇷🇺 RU Server
├── File Manager Website
├── users.db
├── new_users.db
├── uploads/
└── Telegram Bot
        │
        │ HTTP Proxy
        ▼
🇩🇪 DE Server
└── 3x-ui
    └── HTTP Proxy
            │
            ▼
       Telegram API
```

Бот при этом продолжает иметь **прямой доступ к локальным БД и ****`uploads/`**, а сетевые запросы к Telegram API проходят через HTTP proxy.

Это позволяет не переносить базу данных и файлы между серверами.

# ⚙️ Установка

## 1. Клонирование

```bash
git clone https://github.com/m1st1xx/file-manager-telegram.git
cd file-manager-telegram
```

---

## 2. Создание `.env`

Создайте файл:

```text
.env
```

на основе:

```text
.env.example
```

Пример конфигурации:

```env
BOT_TOKEN=YOUR_BOT_TOKEN

PROXY_URL=http://USERNAME:PASSWORD@PROXY_IP:PROXY_PORT

USERS_DB=/path/to/users.db
NEW_USERS_DB=/path/to/new_users.db
UPLOAD_BASE=/path/to/uploads
```

### Переменные

| Переменная     | Описание                              |
| -------------- | ------------------------------------- |
| `BOT_TOKEN`    | Токен Telegram-бота                   |
| `PROXY_URL`    | HTTP proxy для доступа к Telegram API |
| `USERS_DB`     | Путь к основной БД пользователей      |
| `NEW_USERS_DB` | Путь к БД регистрации                 |
| `UPLOAD_BASE`  | Корневая директория файлов            |

# 🤖 Создание Telegram-бота

Создайте бота через **@BotFather** и получите токен.

После этого добавьте его в `.env`:

```env
BOT_TOKEN=123456789:XXXXXXXXXXXX
```

**Не публикуйте токен в GitHub.**

Добавьте `.env` в `.gitignore`.

---

# 🌐 Настройка HTTP Proxy

Если сервер с ботом не имеет прямого доступа к Telegram API, можно использовать HTTP proxy.

Например:

```env
PROXY_URL=http://username:password@1.2.3.4:1080
```

Бот использует proxy только для сетевого взаимодействия с Telegram.

При этом:

```text
Telegram API
     ↑
     │ HTTP Proxy
     │
     ▼
Telegram Bot
     │
     ├── users.db
     ├── new_users.db
     └── uploads/
```

Работа с локальными БД и файлами через proxy не происходит.

# 🔗 Подключение к существующему File Manager

Бот предназначен для работы поверх уже существующего файлового хранилища.

Необходимо предоставить контейнеру доступ к:

```text
users.db
new_users.db
uploads/
```

Например:

```yaml
volumes:
  - ./data/users.db:/app/data/users.db
  - ./data/new_users.db:/app/data/new_users.db
  - ./data/uploads:/app/uploads
```

Таким образом, бот и сайт используют одни и те же данные.

# 👤 Регистрация

Регистрация предназначена для связывания Telegram-аккаунта с аккаунтом файлового хранилища.

Общая схема:

```text
/start
   │
   ▼
Telegram ID
   │
   ▼
Проверка пользователя
   │
   ├── Пользователь найден
   │       │
   │       ▼
   │   Восстановление сессии
   │
   └── Пользователь не найден
           │
           ▼
       Регистрация
           │
           ▼
      Привязка Telegram ID
           │
           ▼
       Личный кабинет
```

Telegram ID используется для идентификации пользователя при последующих запусках бота.

# 🔐 Безопасность

Бот должен работать только с файлами авторизованного пользователя.

Перед операциями с файлами необходимо определить пользователя по Telegram ID и получить его персональную директорию.

Рекомендуется:

* не хранить токен бота в исходном коде;
* использовать `.env`;
* не публиковать базы данных;
* ограничить доступ к HTTP proxy;
* использовать сложные логин и пароль proxy;
* ограничить права Docker-контейнера;
* регулярно создавать резервные копии SQLite БД и `uploads/`.

# ⚠️ Важные ограничения Telegram

Telegram ограничивает размер `callback_data` для Inline Keyboard:

```text
1–64 bytes
```

Поэтому при построении callback-кнопок необходимо учитывать **размер строки в UTF-8**, а не количество символов.

Например, Unicode-имена файлов могут занимать больше байт, чем ASCII-имена такой же визуальной длины.

# 🔄 Совместимость с веб-версией

Одно из основных преимуществ проекта — отсутствие отдельной базы файлов.

```text
             ┌──────────────┐
             │   Website    │
             └──────┬───────┘
                    │
                    ▼
              ┌───────────┐
              │ users.db  │
              │new_users.db│
              │ uploads/  │
              └─────┬─────┘
                    ▲
                    │
             ┌──────┴───────┐
             │ Telegram Bot │
             └──────────────┘
```

Поэтому:

**Загрузка через Telegram**

```text
Telegram → Bot → uploads/
```

становится доступна на сайте.

И наоборот:

**Загрузка через сайт**

```text
Website → uploads/
```

становится доступна в Telegram.

# 📌 Почему этот проект

File Manager Telegram Bot позволяет превратить существующее файловое хранилище в полноценный Telegram-сервис без необходимости создавать отдельную инфраструктуру.

Пользователь получает простой интерфейс:

```text
Telegram
   │
   ├── 👤 Мой аккаунт
   │
   ├── 📤 Загрузить
   │
   ├── 📥 Скачать
   │
   └── 🗑 Удалить
```

при этом серверная часть остаётся общей с веб-версией.
